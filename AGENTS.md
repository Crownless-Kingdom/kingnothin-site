## Site Change Clearance Gate

Before proposing, designing, writing, or implementing a change to the
production site, read `SITE_CHANGE_CLEARANCE.md`.

Potential changes must enter that file at `HOLD` and may be developed only as
notes or as a clearly isolated prototype. Do not edit or connect changes to
`index.html`, `styles.css`, `script.js`, live assets, public navigation,
metadata, forms, links, integrations, or any other visitor-facing production
surface until the user gives explicit final approval and the proposal is marked
`CLEARED`.

A preview request, discussion, experiment, or silence is not final approval.
Clearance applies only to the recorded scope. If that scope expands, return the
proposal to `HOLD` and request clearance again. After implementation and
verification, mark the proposal `APPLIED`.

## Brand North Star

KINGNOTHIN exists to help people remain free in their own minds while learning to navigate the future with privacy, agency, discernment, and wisdom.

Every page, tool, article, visual, service, workshop, product, and partnership should strengthen this. If an idea creates dependence, confusion, fear, or extraction, it does not belong.

## Experience Standard

Help people understand before asking them to act.
Give practical next steps without treating beginners as inferior.
Prepare people for change without turning uncertainty into panic.
Build for the uninitiated, the left behind, and the person who knows something is wrong but cannot yet name it.

People should leave feeling:

- "I finally understand."
- "I can do this."
- "I am not powerless."
- "This place respects my intelligence."
- "I have a practical next step."

Never leave people feeling stupid, frightened, manipulated, overwhelmed, or inferior.

## Voice

Sound like a patient teacher, careful historian, thoughtful scientist, future-facing field guide, and trusted advisor.

Do not sound like a marketer, influencer, motivational speaker, politician, cult leader, doomsday prophet, tech bro, crypto evangelist, conspiracy theorist, or corporate chatbot.

Use the editorial formula:

1. Consequence: what is happening to the person?
2. Mechanism: what system creates it?
3. Meaning: why does it matter beyond the moment?
4. Action: what can be done now?

Name the mechanism. Explain the consequence. Offer the next step. Preserve the reader's dignity.

## Messaging Hierarchy

The message must land before the brand:

1. Insight
2. Context
3. Action
4. Principle
5. Invitation

Use one major tagline per surface. The primary institutional tagline is:

THE REVOLUTION HAS NO THRONE.

Foundational line:

Privacy is the foundation. Agency is the goal. Wisdom is the destination.

## Visual System

The visual system should feel futuristic without becoming science fiction, premium without becoming corporate, industrial without becoming dystopian, ancient without becoming medieval, and rebellious without becoming noisy.

Use:

- Swiss editorial precision
- Near-future industrial design
- Quiet luxury
- Institutional seriousness
- Technical clarity
- Ancient symbolic weight
- Modern accessibility
- Architecture, observatories, maps, civic space, navigation, light, and human craft

Avoid:

- Neon cyberpunk
- Matrix-style code
- Anonymous masks
- Skulls, chains, cages, hacker costumes
- Rain-soaked dystopian cities
- Surveillance cameras as default shorthand
- Chrome AI heads, glowing brains, generic AI imagery
- Glitch overload
- Royal imagery that glorifies domination

## Typography

Mandatory font rule:

- KINGNOTHIN must use only Dosis, Exo, Prototype, and GC-Epic-Pro-Demo.
- No substitute fonts may be introduced unless directly approved as part of a future brand revision.
- Generic fallbacks such as `sans-serif` may only appear at the end of a font stack for browser safety. They must never be used as the visible intended brand font.

Use:

- GC-Epic-Pro-Demo for major hero headlines, section titles, brand statements, tagline moments, interactive reveals, dramatic scroll-triggered text, and high-impact phrases such as "The Revolution Has No Throne".
- Prototype for smaller headings, interface labels, navigation accents, buttons, module titles, callout text, system-style messages, technical UI, cryptographic UI, status indicators, and animated text sequences.
- Dosis for paragraphs, descriptive text, explainers, blog previews, mission copy, longer reading sections, and accessibility-focused content.
- Exo for subheadings, short explanatory blocks, card descriptions, interface microcopy, secondary navigation, feature descriptions, footer text, and form labels.

Do not use:

- Jost
- Space Mono
- Inter
- Roboto
- Arial
- Helvetica
- Montserrat
- Poppins
- Any default system font as a primary brand font
- `monospace`
- `sans-serif` as a primary declared style

Digital type scale:

- Display: 64-104px
- H1: 42-64px
- H2: 30-42px
- H3: 21-28px
- Body: 17-20px
- UI: 14-16px
- Caption: 12-14px

## Layout And UI

Build a digital artifact, not a crowded webpage.

Mandatory symmetry rule:

- KINGNOTHIN should be unapologetically symmetrical by default.
- Major headers, subheadings, section titles, mission statements, high-impact text blocks, introductory paragraphs, closing statements, and calls to action should be centered unless there is a clear aesthetic or functional reason to break the rule.
- Headers and subheadings should be designed to fit on one centered line whenever possible.
- The tagline `THE REVOLUTION HAS NO THRONE` must remain one centered line unless the user specifically asks to span it over two lines.
- Line breaks must never feel accidental. They must feel composed.
- Asymmetry is allowed only as a purposeful disruption for tension, warning, broken-system sections, scroll-triggered disruption, interactive reveals, or visual contrast. After disruption, return to symmetry.
- When in doubt, center the composition.

Principles:

- Content first
- Strong negative space
- Progressive depth
- Asymmetry with order
- Thin rules, restrained surfaces, limited shadows, visible focus states
- Mobile first

Layout mantra:

Trust before conversion. Knowledge before branding. Service before monetization.

## Motion

Movement should reveal cause and consequence.

Use motion concepts such as vault unlock, data redaction, crown dissolve, signal reveal, and progressive disclosure.

Timing:

- Hover and focus: 200-300ms
- Panels: 300-500ms
- Reveals: 500-700ms

No bounce. No elastic easing. No motion that blocks reading. Respect reduced-motion settings.

## Accessibility And Trust

Meet WCAG 2.1 AA minimum.

Use strong contrast, readable body text of at least 16px, comfortable line length and leading, semantic HTML, keyboard navigation, visible focus states, meaningful alt text, screen-reader support, and reduced-motion support.

Never rely on colour alone.

No invasive analytics by default. No tracking pixels. No pre-checked boxes. No dark patterns. No manipulative countdowns. Explain data collection plainly. Prefer local processing and privacy-friendly forms.

KINGNOTHIN must behave as though attention is entrusted, not captured.

## Technical Direction

For the first public static build, use:

- HTML5
- CSS3
- Vanilla JavaScript
- Optional Canvas API
- Progressive enhancement
- Privacy by default

Do not use React, Vue, Angular, Svelte, Bootstrap, Tailwind, Material UI, or jQuery unless the project genuinely outgrows the simple stack and the change is explicitly approved.

## Final Creative Test

Before delivering, ask:

- Does it help people think more clearly?
- Does it strengthen agency?
- Does it respect privacy?
- Does it avoid fear as the primary tactic?
- Does it feel calm, intelligent, useful, accessible, and relevant ten years from now?

If not, revise.
